# Master traceability matrix

The Engineering Brief §8 requires a frozen master traceability matrix that links every build epic to a requirement, object, interface, threat and acceptance test. The Readiness plan §23 requires the trace *requirement → implementation → test → result → evidence link* in the production dossier.

| File | Contents | Generated from |
|---|---|---|
| [requirements.csv](requirements.csv) | All 191 requirements from ZID-REQ-001 (functional, non-functional and §6 regulatory `REG-*`), with priority, verification method, owning units/modules, governing decisions (`DEC-` IDs, see [docs/phases/](../phases/README.md)), test suites, and status/evidence columns | ZID-REQ-001 |
| [acceptance-tests.csv](acceptance-tests.csv) | 762 acceptance tests from every spec's acceptance section, with source and `source_status` | All specs |

Both files are regenerated by `tools/codegen/spec-registries` (the status and evidence columns must then be merged back). Engineering fills `implementation_status`, `test_status` and `evidence_link` as work lands. **A P0 requirement without passing evidence blocks G2 and G4.**
