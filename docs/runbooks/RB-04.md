# RB-04: PostgreSQL writer failover (in-region)

**Services:** all cell services · **Tier:** T0 · **Owner:** @zoiko/sre

## Trigger

Writer unreachable; Aurora/Patroni failover event; `/health/ready` failing on the database check.

## Impact

Writes fail until a single writer is promoted. Reads may continue from replicas within freshness bounds.

## Preconditions

`prod.db.breakglass` only if console automation fails. No step may run before the old writer is fenced.

## Diagnosis

1. Confirm the old writer is unreachable or fenced, not just slow.
2. Read the replication position of each candidate replica.

## Mitigation

1. Fence the old writer (revoke its leases / security group).
2. Drain connections; promote exactly one replica; verify the replication point.

## Recovery

1. Reopen writes; re-seed a new replica; confirm the outbox relay resumed from its committed position.

## Validation

1. No duplicate mandate reservations or evidence sequence gaps (`evidence checkpoint verify`).
2. Writer epoch in `agent.writer_fence` unchanged (in-region failover keeps the cell).

## Rollback

Not applicable: a promoted writer is never demoted back; rebuild the old node as a replica.

## Escalation

SEV1; SEV0 if two writers accepted writes (split-brain).
