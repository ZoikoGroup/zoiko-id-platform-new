# RB-02: Authentication or token endpoint outage

**Services:** authentication · **Tier:** T0 · **Owner:** @zoiko/identity

## Trigger

`authentication-availability` PAGE; synthetic login probe (OPS-11) failing; spike of 5xx on `/oauth2/token`.

## Impact

New sign-ins and token refreshes fail. Existing access tokens remain valid until expiry; revocation still applies.

## Preconditions

Operator Console access at AAL-Z3. Key-related actions need the KMS runbook (RB-11).

## Diagnosis

1. Split failures by endpoint (`/oauth2/token`, `/oauth2/authorize`, `/authn/webauthn`) and by client.
2. Check signing: KMS/HSM latency and throttling for the token signing key (RB-11).
3. Check session store writes and database health (RB-04/05/06).
4. Check federation: a single upstream IdP outage affects only its connection (`federation.connection.*`), not native passkey sign-in.

## Mitigation

1. Upstream IdP outage: mark the connection degraded; native passkey sign-in continues. Never fall back to an unverified identity link (SRE-30).
2. Signing throttled: reduce non-critical signing (credential issuance) before token signing; never use a non-HSM key.

## Recovery

1. Restore the failing dependency; drain queued step-up challenges; confirm refresh-token rotation resumes.

## Validation

1. Synthetic passkey login, refresh and revoke succeed in every cell.
2. 5xx rate on token endpoints back under SLO.

## Rollback

Re-enable any connection marked degraded only after its health probe passes.

## Escalation

SEV1 for any T0 sign-in outage beyond 5 minutes; SEV0 if signing-key misuse is suspected (RB-16).

## Evidence

Incident record; any key action leaves its own key-management audit record.
